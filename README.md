# 現場報到系統

臺北醫學大學楓杏醫學青年服務團 — 子活動現場報到 / 簽退系統。
Next.js 14（App Router）+ Supabase。

目前版本：**v0.5.0**（全部五個階段完成）

---

## 一、建立 Supabase 專案

1. 到 supabase.com 開一個**全新專案**（不要與義診、測驗系統共用）。
2. 進入 **Authentication → Providers → Email**：
   - 開啟 Email provider
   - **關閉 Confirm email**（系統不寄信，帳號由管理員建立）
   - 關閉 Enable email signups（不開放自行註冊）
3. 進入 **SQL Editor**，依序執行 `supabase/migrations/` 下的 SQL（`20260917000001_init.sql` → `20260917000002_roster.sql`）。
4. 到 **Project Settings → API** 抄下三個值：Project URL、anon key、service_role key。

## 二、本機設定

```bash
npm install
cp .env.local.example .env.local   # 填入上一步抄下的三個值
```

`NEXT_PUBLIC_ACCOUNT_EMAIL_DOMAIN` 是帳號在內部合成信箱時用的網域，
使用者永遠看不到它，維持預設 `checkin.local` 即可。

建立第一個系統管理員：

```bash
npm run create-admin fxadmin 系統管理員
```

啟動：

```bash
npm run dev
```

打開 http://localhost:3000 ，用 `fxadmin` / `fxadmin` 登入，系統會要求你立刻設定新密碼。

## 三、帳號規則

| | 系統管理員 | 註冊長 | 註冊組員 | 報到人員 |
|---|:--:|:--:|:--:|:--:|
| 建立系統管理員 / 註冊長 / 註冊組員 | ✅ | ❌ | ❌ | ❌ |
| 建立報到人員 | ✅ | ✅ | ❌ | ❌ |
| 變更他人身分 | ✅ | ❌ | ❌ | ❌ |
| 重設 / 停用 / 刪除 | 全部帳號 | 只限自己建立的報到人員 | ❌ | ❌ |

- 登入使用**帳號**而非信箱，限 6–20 字元英數字與底線。
- 新帳號的**初始密碼與帳號相同**，首次登入強制變更（至少 8 字元、不可與帳號相同）。
- 沒有信箱可寄驗證信，忘記密碼一律由上層在後台重設回初始值。
- 帳號下限是 6 字元而非更短，因為初始密碼等於帳號，而 Supabase 的密碼下限為 6。

## 四、資料表

| 資料表 | 用途 |
|---|---|
| `app_users` | 使用者與角色 |
| `sub_events` | 子活動（含 `require_checkout`、`min_stay_minutes`） |
| `participants` | 人員主檔，`code` 編號與 `qr_code` 全域唯一 |
| `registrations` | 參與名單 = 人員 × 子活動，組別存在這裡 |
| `attendance_logs` | 報到 / 簽退紀錄，含撤銷稽核欄位 |
| `sub_event_grants` | 註冊組員的子活動授權 |
| `import_batches` | 匯入批次（可回溯） |
| `app_settings` | 全域設定（報到畫面預設顯示欄位） |

兩個關鍵索引：

- `attendance_logs_active_key` — 同一筆名單的同一種紀錄（報到 / 簽退）同時只能有一筆未撤銷，兩台裝置同時掃同一人也只會成立一筆。
- `attendance_logs_client_key` — 離線佇列的冪等鍵，重送不會重複寫入。

## 五、名單匯入

1. 到「子活動」建立活動，進入該活動頁。
2. 在「匯入名單」選擇 Excel 或 CSV（讀第一個工作表，第一列為標題）。
3. 系統會自動猜欄位對應，確認後匯入。至少要有**姓名**與**編號**；沒有 QR 欄位時以編號作為 QR 內容。
4. 其他欄位選「其他欄位（保留）」會存進 `extra`，之後可在報到畫面選擇顯示。

編號是全系統的人身分鍵，會自動去空白並轉大寫。同一個編號再次匯入時，
會沿用同一個人與同一張 QR，只更新該子活動的組別與欄位。
每次匯入都會留下批次紀錄，可以整批復原。

## 六、現場報到

進「現場報到」選子活動後進入掃碼畫面。

- **掃碼**：條碼槍不必開相機，直接掃即可（畫面的輸入框會自動保持聚焦）；
  手機則按「開啟相機掃碼」。輸入間隔小於 60 毫秒判定為掃碼，否則記為手動輸入。
- **模式切換**：開啟簽退的活動，上方有「報到模式 / 簽退模式」。
  簽退**不會**由掃碼自動推進——報到模式下重複掃同一人只會顯示「已報到」，
  不會誤簽退。
- **重複掃碼冷卻**：同一組條碼 3 秒內重複讀到會被忽略。
- **最短停留**：簽退時若距離報到未達子活動設定的分鐘數，會跳出確認才放行。
- **手動搜尋**：條碼沒帶或壞掉時，用姓名／編號搜尋後按一下完成，
  紀錄會標記為手動並記下操作者。

結果面板整片變色（綠＝成功、藍＝簽退、黃＝重複或需確認、紅＝異常），
並附短促提示音與震動，現場吵雜或昏暗時也能判讀。

## 七、離線作業

場地訊號不穩時，報到不會中斷：

- 進入報到畫面時，整份名單會存進瀏覽器的 IndexedDB。
- 斷線後掃碼改用本機名單比對，姓名與組別照常立刻顯示，
  報到寫入本機佇列，畫面標示「離線記錄，稍後同步」。
- 頂端狀態列顯示連線狀態與待同步筆數，恢復連線會自動送出，也可手動「立即同步」。
- 線上掃碼時若請求失敗，會自動改走離線流程，不會讓現場卡住。

**衝突怎麼處理**：每筆離線紀錄都帶著掃碼當下的時間戳與一組唯一鍵。
同一人被多台離線裝置各報一次時，**以最早發生的那筆為正式紀錄**，
其餘存為重複紀錄（`duplicate_of`）保留下來，不會被丟棄，也不會覆蓋別人的。
重送同一筆不會產生第二筆。

**兩個限制要知道**：

1. 報到畫面必須**先在有網路時開過一次**。Service Worker 會把頁面外殼快取起來，
   之後斷線重新整理仍打得開；但完全沒載入過的裝置在離線狀態下無法第一次進入。
   實務上請在出發前、或到場還有訊號時先各裝置開一次。
2. Service Worker 只在正式部署（production）啟用。`npm run dev` 不會註冊，
   以免快取到開發中的檔案。要測離線請用 `npm run build && npm start`。

## 八、報到紀錄與系統設定

**報到紀錄**（所有身分可進；報到人員只看得到自己經手的紀錄）
選子活動後顯示總報到率、各組進度與目前在場人數，
並隨現場報到即時更新。逐筆紀錄可依類型與關鍵字篩選，
註冊長以上可撤銷誤判的紀錄——撤銷報到會連帶撤銷該人的簽退。
「匯出 Excel」產生完整名單，含報到／簽退時間、操作者、方式與停留時間。

**系統設定**（限系統管理員）

- **離線報到開關**：關閉後斷線時掃碼直接顯示「離線報到未開放」，
  不寫入本機佇列。
- **報到畫面顯示欄位**：勾選要顯示的欄位、調整標籤、字級與順序。
  除了姓名／編號／組別，可加入匯入 Excel 時帶進來的任何欄位（填該欄的標題）。
